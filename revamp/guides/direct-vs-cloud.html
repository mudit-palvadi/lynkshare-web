Choosing a mode

Direct vs Cloud transfer: which should I use?

Both modes send the same encrypted file. The difference is where the encrypted bytes wait and whether both people need to be online at the same time.

The short answer

SituationUse
Both people are online nowDirect, for the shortest path
The recipient will open the link laterCloud
Safari/iOS receiverCloud is usually the reliable path
Large file on AndroidDirect if both are online; otherwise Cloud
Restrictive network or firewallCloud, or let Direct fall back

How Direct works

Direct tries to connect the two devices and stream the encrypted file between them. Both devices must be online, and the network must allow a peer-to-peer path. If the connection cannot open, LynkShare can continue with the encrypted Cloud copy instead of making you start again.

Direct is best when both people are ready at the same time. It avoids storing a cloud copy for the transfer, but the connection can still expose network addresses to the other peer and the connection service.

How Cloud works

Cloud encrypts the file, uploads the ciphertext, and lets the recipient open the link during the session. The sender can finish before the recipient is ready. The encrypted object is stored temporarily and is deleted by the bucket lifecycle within 24 hours, or immediately when the transfer is cancelled.

Cloud is the right choice for remote recipients, delayed opening, browser-only receivers, and networks that block direct connections. The web limit is 10 MB total per transfer.

Limits

The web sender allows 10 MB total per transfer. The Android app allows 15 MB Cloud and 20 MB Direct on the standard tier, or 30 MB Cloud and 50 MB Direct after the in-app unlock. A transfer can contain up to 10 files, and the service ceiling is 50 MB.

Privacy difference

Both modes encrypt the file on the sender's device. Cloud stores ciphertext and session metadata; Direct streams ciphertext between the devices. In both cases the server does not receive the file key. Direct can expose network addresses to the other peer; a TURN relay can see connection metadata, not plaintext.
